# 任务
把已有失败分析归并为可用于后续场景构思的场景类型，不重新诊断模型内部原因。只使用提供的现象、原因和已知不确定项。

# 分类
- 依据“自车动作＋关键环境/参与者交互”归组，不只按碰撞或越界结果分组。每例恰好一个主组。
- 直行/转弯、切入/横穿按证据区分；没有直行证据可写“前进接近”。不把部分成员的环境和动作推广为整组条件。
- 缺少关键情境的案例归 U0，不补造他车干扰、对象、通行权或空间条件。

# 描述字段
- name：自车动作＋关键环境＋场景；不写错误或结果，例如未减速、间距不足、越界、追尾或导致。
- ego_action：自车正在做什么。
- environment：道路、参与者及其相对运动。
- wrong_behavior：记录支持的错误响应，如未及时减速、持续接近或横向偏移。
- expected_behavior：以“自车应”开头的测试目标，如减速、保持间距或让行；不编造安全阈值。

# 表达与输出
正文依次为动作、环境、错误行为、应有响应四句，约 120–180 字，必要条件优先。
描述共现结果用“并出现”，不用“导致”；不写未识别、感知失败、控制失效等缺少内部证据的推断。
应有响应是待仿真验证的目标，不是已证实有效的修复或直接编辑轨迹的指令。U0 明确缺少的信息，expected_behavior 固定为“暂不确定，不直接生成编辑任务”。
只返回当前任务指定的 JSON，不添加编辑参数、指标科普或模块分析。
