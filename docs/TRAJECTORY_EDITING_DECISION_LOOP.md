# 攻防编辑的决策输入与预算

新运行默认将攻击事件放在 **1.5–7.5秒**，与当前07评分窗口一致。轨迹编辑、减速和转向准备可从0秒开始。粗规划、攻击验收、冻结检查和独立复核使用一致的时间含义；原生时间戳舍入按1毫秒容差处理，不改变几何距离或物理限制。

## 硬要求和优化目标

保留初始姿态、连续运动、道路/其他车辆、原生回放及明确的调用者任务契约检查。调用者通过 `task_contract` 明确要求的关键帧仍是硬要求。

新05入口取消 contact/near_miss/either/allowed 交互分类，也没有隐藏的默认 either、必须接触或0.15–2米近险门槛。Agent 自拟关键帧是构造优化偏好；偏好未完全达到时返回实际偏差。候选仍需满足配置的事件窗口、明确的调用者契约和轨迹检查，由 Agent 结合图像、净距、接触及时间证据判断任务符合性。不能将参考几何通过描述为 VADv2 已被攻击成功。旧归档的旧分类只用于解释历史记录，新工具入口不接受该字段。

默认不因事件开始前净距小于2米而拒绝轨迹；早期实际接触仍受事件边界检查。真正过长的保持时长继续拒绝，仅修复端点对齐使原本合法时长超限的情况。

## 图文输入

- 05选车与初次编辑均提供BEV，包含道路、车辆ID、自车参考路径和目标轨迹。两幅快照展示初始布局与事件窗口内的相关时刻。
- 构造后自动提供至多两张候选轨迹图，供下一次决策比较；其他候选仍可通过检查工具查看。布局图和策略测试叠图不替代最终候选图的交付检查。
- 06冲突理解提供冻结场景BEV，原始相机图片可作为编辑前的道路证据；编辑阶段首次请求也提供布局图，后续使用候选检查图。
- 文本保留任务、相关车辆关键状态、候选指标、失败原因和预算。车辆相关性按全时段接近情况筛选，展示至多12辆；这不是候选质量排名。完整车辆、原生时间戳和原始精度仍参与数值检查并保留在产物中。
- BEV与轨迹图均为几何图，不是相机渲染或策略仿真。图片是否减少总API耗时需真实实验确认，不能从单次调用推断。

## 保存与续跑

05/06返回 `native_export`，包含导出状态、失败原因和报告路径，主Agent上下文保留这些字段。`simulation_input=null` 表示尚无可执行原生包，不能猜测目录，也不能用原始未编辑场景替代。

已有06专家只需重新导出时，传相同 `attack_result`、`target_effect`、停止/进度选项，设置 `export_only=true`、`reuse_completed_from=<已完成06服务目录>`。该路径核对任务/攻击版本，独立复核保存的专家CSV，复制原轨迹及证据到新输出目录并导出；不会运行模型、构造器、FOCI或渲染。普通 `reuse_completed_from` 仍表示复用准备阶段后进入编辑，不等同于仅导出。

约2Hz输入的导出时间轴允许最多5毫秒的累计网格偏差和单帧间隔偏差（同时不超过名义步长的1%）。按原帧索引统一名义时间，保留原帧、相机对应关系和全部姿态，重算速度；原始时间戳和逐帧偏差依据保存在导出报告/元数据。明显不均匀和丢帧仍要求处理，不补造帧。该对齐不改变1.5–7.5秒评分范围。

`reuse_completed_from` 指向之前的05服务运行目录。只允许同一实验区域内、场景/目标/指令及任务和物理约束匹配的检查点。阶段时间预算可调整，其他语义变化不能伪装成同一次续跑；不兼容时明确报错，不静默从头重算。

合格候选、控制命令和检查证据保留在磁盘。编辑预算耗尽或动作次数结束时，有合格候选可获得至多两次收尾动作和一次90秒收尾宽限，只能检查、测试、提交已有候选或诚实结束，不再构造新轨迹，也不自动替Agent选择候选。

## 累计预算

主Agent通过持久化任务执行05时，预算按 `execution_scope` 保存在任务存储的 `attack-budgets/<scope>/`，同一对话重试、重新规划或更换服务输出目录不重置：

| 项目 | 默认限制 |
| --- | --- |
| 构造器内部评估 | 累计1000次，每次构造最多200次 |
| 模型逻辑调用 | 累计18次，内部HTTP重试耗时也计入 |
| 模型调用时间 | 累计900秒 |
| 收尾预留 | 上述总额内预留2次调用和90秒，仅供合格候选收尾 |

`timeout` 是整个工具的超时，默认3600秒；`stage_timeout_s` 是攻击轨迹阶段预算，默认420秒。提高其中一个不会刷新累计预算。中断的在途请求在下次调用时结算一次，最多按其原请求时限计费。

累计预算耗尽且没有可用候选时结束并报告，不通过再次调用05获得新预算。新对话有新的执行作用域。独立调用、没有主Agent任务身份的工作流使用自身目录预算。

## 验证

01失败分析先提供首次违规附近最多三个总览关键帧（缺少违规时刻时用开头/中间/结尾）及对应的ego/actors数值；同一数值查询复用证据ID，已看图片不重复发送。每次最多三张新补图，总计最多六张；仍然要求逐候选数值证据核验，不把缺失数据当零。`trace.json` 和 `evidence-budget.json` 记录查询和图片使用。

流式请求失败保留错误类型、阶段和归档引用；阶段/单请求超时与普通执行错误分开报告。模型工具JSON错误进入有次数限制的格式纠正，不执行不完整参数，也不当作轨迹不可行。04缺标注/相机、场景Gaussian资产或源图像时直接返回 `needs_information`，无需模型调用；缺道路地图仍沿用提示而非04硬拦截。

离线测试覆盖：原生时间戳与保持时长、事件边界、硬契约/优化偏好、图像交付、跨目录检查点、累计预算、晚生成候选的收尾、原生导出和防御接口。

真实场景控制重放用于检查工具和独立复核，不代替新的模型决策或 VADv2/PDM 实验。改动后的效果应从新对话重跑相同案例，比较成功率、API总时间、无效调用数和编辑次数。

## MTGS渲染标定与UTM高程（2026-11-16）

NuPlan标注的UTM高程可能相对重建路面持续漂移；路块中间切入的场景在第0帧也可能已经漂移。`frames[*].ego2global`仍用于原有轨迹/标注坐标，不能作为MTGS的高度或俯仰/横滚参考。

原生导出使用 `source_asset/video_scene_dict.pkl` 中与场景token和Gaussian资产绑定的重建位姿。新包 `native_export.version=edited_scene.v2`，`ego_calibration_frame=reconstruction`；保留整块重建参考位姿，原生MTGS按最近XY查询Z与倾斜，不再重复减重建平移。元数据记录源路径、SHA256、路块原点、参考数量和精确token覆盖数。场景后段超出重建时间范围时仍是最近XY查表，不声称补造了对应重建帧。

05攻击、新增车和06单/三视角渲染共用该标定读取器。渲染XY/yaw仍由指定轨迹控制；高度基于重建位姿相对road_height_map的实测离地量，编辑位置变化时跟随当地路面，倾斜来自最近重建位姿。高度参考不再取首帧UTM Z，也不硬编码成固定0.35米。缺重建标定、无法绑定或原点不匹配时明确失败。

原始记录轨迹的对照视角遇到路面缺测时，可像原生MTGS一样使用最近重建参考位姿的Z/倾斜，并在逐帧报告中标记路面高度未知；不以UTM高程填补缺测。编辑后的候选视角仍要求可靠的路面高度，原始对照图的缺测不会单独阻止已有效编辑轨迹的回放。

旧的 `edited_scene.v1` UTM标定包在原生策略评测前明确拒绝，避免继续消费地下相机图像。可复用已保存的05/06轨迹重新导出，无需重新调用攻防Agent。旧视频、评分和后训练产物保留为排查记录，新结论须使用修复图像后重跑07及需要的后续阶段。

## 07冷启动计时

原生07自动在 `result_dir/startup_timing/` 写分进程计时，完成或正常异常退出时汇总到 `summary.json`；工具返回 `startup_timing_report` 路径，主Agent上下文只保留路径。记录框架/插件导入、配置、模型构建、CPU权重加载、CUDA模型就绪、Gaussian资产加载和模型准备、首帧渲染、历史帧等待、首条规划及首次模型推理。

记录的是CPU墙钟时间，不额外强制CUDA同步；嵌套阶段与两个并行进程的时间不能直接相加。fork子进程有独立记录，不覆盖父进程；中断时尚未结束的阶段保持running供排查。计时不缓存或替换模型，也不改变历史帧、评分窗口、轨迹或奖励设置。

仅诊断07时可设置 `with_dense_reward_manager=false`，保留原生官方评分和视频，结束后不执行09；需要RLFT奖励数据时保持true。计时本身不需要新增工具参数。下一次真实07运行才能测得本机VADv2完整启动细分耗时。

## 04粗规划的图文输入与按需轨迹查询

v4粗规划不再以原车未来的倒车/侧滑估计否决场景；详细初态支持与生成轨迹检查由05执行。全程有效车辆标注仍是当前05兼容要求，原记录30米距离/落后10米仅作提示。现有车操作保持t=0姿态，不支持瞬时搬位；新位置的全程静止障碍可用add_vehicle/stationary表达。

初始输入保留相机拼图，并在原始坐标可用时增加含自车记录路径的BEV。全部车辆ID保留为简短目录，非车辆用数量摘要，原始精度证据另存。BEV标签只覆盖部分车辆，省略对象不代表不存在；原图、BEV和轨迹均来自原始场景，不是攻击后的渲染或策略仿真。

内部 `request_trajectory` 按精确车辆ID（或ego）返回轨迹图和最多24个采样观测点，最多3次查询。重复查询复用证据，缺观测不补造。相机补看预算仍为2轮、每轮最多2个相机。这些是04内部动作，不增加主Agent工具。

## 04多方案与05内部选择（v5）

04在同一次审查中考虑编辑已有车辆和新增车辆；需要编辑时，输出1–3个不分排名的 `edit_options`，通常两个足够，不为凑数编造方案。每个方案记录 `option_id`、`operation`、可选的已有车辆 `target_track` 或新增车辆 `maneuver`、粗略 `instruction`、理由 `rationale` 和待核实项 `uncertainty`。04不构造具体轨迹。

04程序生成的 `attack_input` 使用 `operation=auto`，把同一组方案放在 `plan_options`，并携带可用的车辆素材；主Agent应完整转交，不能先选定方案再把05锁成固定车辆。新增车辆所需素材应尽量随第一次04请求提供；缺素材但有已有车辆方案时仍可执行，只隐藏新增车辆工具。只有新增方案且缺素材时返回 `needs_information`，补充相同任务的素材后复用粗规划，不重新调用模型。

05根据场景证据选择或调整一个方案，不要求逐一尝试。方案是建议，不能自动转成硬 `task_contract`。选车阶段有BEV及失败反馈；已有车辆起始姿态不支持时可在05内重新选择，编辑Agent也可调用 `request_object_reselection`。最多切换两次，同一次工具执行共享累计API、构造评估、剩余编辑次数和阶段时限；失败信息仅传车辆ID、原因与检查项，不复制旧对话。切换耗尽且无通过候选时诚实失败。最终冻结场景只包含一个被选中的编辑/新增车辆。

输出 `operation`、`target_track` 是最终实际使用的操作与车辆，`plan_choice` 保存关联方案、选择理由和操作/目标调整信息。旧的直接 `edit_existing` / `add_vehicle` 输入仍可使用，调用者显式固定的操作或车辆不因自动选择机制改变。已有车辆仍不能瞬间搬位；新增车辆可在有效新位置以零速开始。低速初态、运动学和道路验收阈值没有通过本次改动放宽。

验证使用离线模型响应及模拟的编辑器结果，覆盖真实工具消息解析、04→05参数传递、缺素材缓存、内部换车、预算/时限继承与失败终止；不等于真实模型已找到更优攻击，需要新实验确认。
