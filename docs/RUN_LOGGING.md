# 全流程日志与计时

对话续跑后端会为每次追问建立独立运行目录，并在 `run.json` 记录父运行与对话 ID；本轮计时不重复累计旧轮 API 消耗。接口及当前前端接线状态见 [对话续跑](CONVERSATION_CONTINUATION.md)。

从前端启动主 Agent，或执行 `python -m agent.main "任务"`，都会自动在 `logs/run_时间戳/` 建立本轮日志。无需额外开关。前端任务结束后的“查看本轮日志与计时报告”可直接打开报告。新日志功能仅作用于更新后启动的任务。

## 先看哪些文件

| 路径 | 内容 |
|---|---|
| `REPORT.md` | 按模块汇总工具耗时、累计 API 耗时、API 次数、重试、错误、未完成请求和编辑尝试，另表列出输入规模峰值 |
| `summary.json` | 机器可读报告，另含 Token 用量、usage 覆盖次数、重试和主 Agent 纠错次数 |
| `api_requests/<request_id>/request.json` | 每次实际请求的消息、工具定义、模型参数及端点，已脱敏 |
| `api_requests/<request_id>/response.json` | 模型公开回答、工具调用、usage；不复制模型私有推理/不透明续传正文 |
| `api_requests/<request_id>/result.json` | 请求所属模块、主步骤、尝试编号、起止时间、耗时、首响应时间、错误类型、HTTP 状态和输入规模 |
| `tools/step_编号_工具名/` | 主 Agent 工具输入、输出、调用关联 ID、`timing.json` 及执行日志 |
| `tool_events/` | 05/06 子 Agent 实际工具调用、结果及执行耗时，关联原始存档位置 |
| `operations/` | 编辑内部阶段的计时记录，保留父事件 ID 和原始文件位置 |
| `assets/` | 请求中的 base64 图片/视频按内容哈希去重保存；请求中保留文件引用、类型及大小 |
| `snapshot/` | 启动时的提示词/配置副本、代码文件 SHA256、Git HEAD 和未提交文件清单 |
| `run.json`、`agent.jsonl`、`state.json`、`final_state.json` | 任务元数据、主 Agent 决策及状态检查点 |

当前接入主 Agent、02/04 通用 LLM、01 失败分析、03 检索聊天/embedding/rerank、05/06 编辑请求。原有编辑后端请求存档仍保留，新 `result.json` 的 `archive_ref` 可定位它们；统一报告只统计 `api_requests/`，不会把两份存档重复相加。

## 计时口径

- **运行总耗时**：主 Agent 本轮开始到结束的时间。
- **工具总耗时**：主 Agent 从发起工具到收到最终结果的时间，包含排队、子 Agent、构造、FOCI、仿真和渲染等。异步等待不会另计为一次工具执行。
- **累计 API 耗时**：每次网络请求的等待、生成、接收/解析处理时间累计，包含失败、超时和显式重试。请求上下文写盘在计时前完成；流式处理本身已有的增量落盘开销仍处于接收区间内。API 时间包含在工具耗时中，不能相加；并发 API 累计时间可以超过运行总耗时。
- 主 Agent 纠错每次分别存档，并累计到前端该步 API 计时，避免只计最后一次。`retry_requests` 表示尝试编号大于 1 的请求，编辑循环恢复后对同一目录、同一轮次再次发起的请求也计为重试；`main_correction_requests` 是其中主 Agent 纠错部分，两列不能相加。
- `first_response_seconds`：流式请求第一次收到 chunk 的时间；非流式 HTTP 是收到响应对象的时间；非流式 SDK 通常是完整返回时间，不能视为首 Token 时间。
- Token 数以服务商 usage 为准。缺失时只保存字符数、请求字节数、图片数量和工具定义大小，不把字符估算冒充 Token。
- 编辑次数按**实际归档的编辑工具调用**计数，包含预览、参数校验失败和被拒绝的尝试。构造器/FOCI 一次生成多个候选仍计一次调用；选择、看图和提交不计编辑。
- 内部 `operations/` 包含嵌套阶段，供定位构造/FOCI/检查/渲染耗时，不直接加到工具总耗时中。

报告在主 Agent 决策、工具结束和运行结束时更新。长工具执行期间逐次请求和子工具档案仍实时落盘，报告可手动刷新：

```bash
environments/agent/.venv/bin/python -m common.run_report logs/run_具体时间戳
```

## 中断与版本追溯

请求发出前会先写 `status=running`。正常返回、超时或捕获到的中断再更新；若进程被强制杀死或服务器重启，仍保持 running 的记录会列为“未完成请求”，无法得知的最终 API 耗时不会伪造。手动重新生成报告不会重新调用 API。

记录通过运行 ID、工具调用 ID、步骤及环境传入子进程；同一轮的并发请求各占独立目录。子工具事件按原始存档路径去重，恢复时不会重复统计同一份存档。

快照只保存提示词和配置内容，代码保存哈希；有未提交修改时仅凭 Git HEAD 不能精确恢复代码。运行中修改提示词/代码也不受启动快照保护，但每次 API 请求仍保留当时实际发送的上下文。比较模型时建议保持代码不变。

## 脱敏与体积

统一请求日志不写认证头；已知环境密钥、显式传入密钥和敏感字段会替换，URL 查询参数去除。`.env` 不复制到快照。base64 媒体单独保存一次，不在每次请求重复展开；JSON 消息内容仍按实际请求保存，便于检查上下文增长。服务商私有推理续传字段只保留省略标记和长度，不加入分析上下文。

日志包含场景数据与模型公开回答，默认保存在本项目内，不自动上传。
