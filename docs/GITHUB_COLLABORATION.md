# adagent GitHub 协作与敏感信息规范

目标仓库：https://github.com/1658821932/adagentv1.0

适用范围：nuPlan候选数据库、工具4检索、Kimi适配与工具6的ADSceneGraph数据转换。后续由开发助手按照本文执行，用户不必手动操作Git。

本文先作为迁移方案。远端默认分支已确认是main（核查版本07617b3718099e286d59673a52f25e1e81e76941）；现有贡献规范、分支保护和推送权限尚未核实，不能把本文建议当作仓库已启用的设置。仓库已有的AGENTS.md、CONTRIBUTING、PR模板等应在开始修改前阅读并遵守。

## 1. 当前工作与迁移原则

- 原项目 `ghc/adagent` 继续只读；现有实验副本为 `hzy/adagent`，保留其代码、密钥、数据和运行产物。
- 现有副本不是干净工作树：包含复制时已有的暂存改动和本次nuPlan修改。不能直接把整个副本推到新仓库，也不执行 `git add .` / `git add -A`。
- GitHub仓库将作为后续代码协作来源。先获取其最新版本，在独立干净checkout建立功能分支，再按明确文件清单迁移本次修改；不覆盖远端已有的更新。
- 不把旧副本的 `.git`、提交历史、环境或数据复制进新checkout。不盲目合并来源不明的旧历史。
- 迁移前比较共同文件，保留队友的接口修改；每个冲突按最终接口解决，不整文件选择“ours/theirs”。
- 已运行的索引与训练任务继续使用原实验目录。准备和验证新checkout后再切换运行入口，避免运行中替换代码或搬走数据。

## 2. 哪些内容可以提交

| 内容 | 处理方式 |
|---|---|
| 检索/转换/重建适配源码、必要测试 | 提交 |
| 安装说明、接口说明、协作规范、依赖清单 | 提交 |
| 不含凭据的网关地址、模型名、采样设置 | 可提交；本机路径改成可配置项 |
| `.env.example`、配置模板 | 可提交，密钥字段必须为空或明显占位符 |
| 少量合成测试数据 | 可提交，不能含真实凭据或原始受限数据 |
| 实际 `.env`、任何环境的密钥文件 | 仅保存在本地 |
| GitHub PAT、API Key、OSS密钥、私钥、带认证的URL | 不进入代码、文档、日志、截图、提交说明或PR |
| nuPlan视频、原图、LiDAR、地图、候选数据库、SQLite索引 | 本地/获授权的数据存储；代码库提供构建脚本和说明 |
| checkpoint、PLY、渲染视频、抽帧缓存、运行日志 | 本地实验产物，不随源码上传 |
| Python环境、CUDA缓存、解压的系统动态库 | 不上传；提供依赖与复现说明 |
| 本机绝对路径清单、复制清单、原始运行报告 | 默认本地保留；公开报告使用相对路径和汇总统计 |

即使仓库为私有，也遵守同样的凭据规则。Git LFS解决大文件存储问题，不适合存放密钥，也不自动解决数据授权问题。

## 3. API Key 如何配置

本地 `.env` 使用专用密钥，可以加双引号，例如：

```dotenv
KIMI_API_KEY="在本地填写真实密钥"
```

仓库里的 `.env.example` 应写成：

```dotenv
KIMI_API_KEY=
```

代码从环境变量或本地配置读取密钥，不硬编码。网关地址和模型名可以放在普通配置中。网络诊断不打印Authorization、完整请求体、环境变量全集或带认证的URL；错误信息需要脱敏。

开发助手不会将密钥写入命令参数、commit message、issue、PR描述或聊天。GitHub认证使用SSH或凭据管理器，remote URL不内嵌PAT。未来CI若确实需要外部模型，再单独配置GitHub Secrets；常规测试使用mock，不调用付费API，不让外部PR获得密钥。

## 4. 忽略规则与检查

当前本地 `.env` 未被跟踪，但忽略规则仍需补充。迁移时按远端实际目录应用以下规则，不能未经检查整段覆盖远端 `.gitignore`：

```gitignore
# 本地凭据；保留无密钥的示例
.env
.env.*
!.env.example
!.env.*.example
.secrets/
**/.secrets/
**/secrets/
*.pem
*.key

# 本项目新增的本地数据与产物
/artifacts/
/runtime_libs/
/WORKSPACE_COPY_MANIFEST.json
/mcp_servers/sentry_video_search/data_nuplan/
/mcp_servers/sentry_video_search/runtime/

# 通用实验与环境文件：与仓库原规则合并
__pycache__/
*.py[cod]
.pytest_cache/
.venv/
/environments/
*.sqlite
*.sqlite3
*.db
```

不要为省事忽略所有JSON/YAML：其中包含必要的源码配置。模型、视频和第三方资产的规则按具体目录设置，保留远端已有的合法小型测试资产。

`.gitignore` 只影响未跟踪文件；已经跟踪或已进入历史的秘密不会因此消失。检查必须覆盖工作树、暂存区与拟推送的提交历史。若需取消跟踪已有本地配置，先核实文件归属，再定点处理，不删除实际本地密钥文件。

提交前执行：

1. 列出本次允许提交的文件，区分本次修改、原有修改和运行产物。
2. 只暂存明确文件或选定补丁，查看 `git diff --cached --stat` 和逐项diff。
3. 对候选文件、暂存内容和拟推送历史做密钥扫描；报告只包含文件/位置/规则名，不显示匹配原文。
4. 检查大文件、外部路径、符号链接和敏感运行记录。
5. 执行 `git diff --check` 和相关测试。
6. 第一次迁移额外核查远端历史；工作区没有密钥不等于历史没有密钥。

本地自定义扫描只是补充检查，不能保证发现所有未知格式秘密。执行时优先结合可用的专业secret scanner与人工diff审查。

## 5. 分支、提交与PR

- 从核实后的远端默认分支创建功能分支，例如 `hzy/nuplan-retrieval`；不直接向默认分支推送功能开发。
- 一个分支解决一个可评审的问题。按接口、数据准备、Kimi检索、ADSceneGraph交接等清晰边界拆分提交或PR；有依赖的修改在描述中说明。
- 每个commit说明具体变化，例如 `feat: add nuPlan scene manifest handoff`，不夹带队友的历史改动、环境文件或实验输出。
- 推送前fetch远端；自己的未共享分支可按需rebase，已共享分支不擅自重写历史。不向默认分支force push，不清理他人分支。
- PR说明问题与新行为、涉及接口、验证命令和结果、数据如何获取及已知限制。只链接团队可访问的脱敏证据，不粘贴本机私有日志。
- 真实API/重建与mock测试分开列明，未完成的300场景索引或全量验收不写成成功。
- 冲突解决后重跑受影响检查；经过评审后再合并。默认分支保护、必须检查、review人数由仓库维护者配置，不假设当前已开启。

首次对外推送前，开发助手应准备完整的可审查diff、扫描结果和测试结果。本次“先写文档”不等于授权把现有实验目录整体上传；尚未执行任何推送。

## 6. 新手需要理解的几个词

| 名称 | 在本项目里的意思 |
|---|---|
| clone | 从GitHub取得一份本地代码 |
| branch | 独立开发分支，不直接影响默认版本 |
| commit | 本地保存一组明确的代码改动 |
| push | 将提交发送到GitHub，凭据检查必须在此之前完成 |
| PR | 请求队友查看并合并这组改动 |
| merge | 把评审后的修改合入目标分支 |

用户主要需要确认功能目标和评审结果。分支整理、差异比较、扫描、测试和PR材料由开发助手处理；遇到接口取舍或真正需要权限的动作时再说明具体原因。

## 7. 如果发现密钥已经泄露

立即停止继续传播，先撤销/轮换泄露密钥，再联系仓库维护者处理历史、PR、fork及协作者副本。只删除最新文件或新增 `.gitignore` 不足以清除历史。历史重写会影响队友，不自行force push整个仓库。处理记录不包含泄露值。

## 8. 下一步执行顺序

1. 核实GitHub仓库可访问性、默认分支、现有规范和本地remote对应关系。
2. 建立独立干净checkout与功能分支，先落实忽略规则和secret检查。
3. 比较远端与实验副本，只迁移本次nuPlan相关修改，保留既有未提交工作。
4. 完成环境路径配置；数据、凭据、索引和checkpoint留在本地。
5. 恢复未完成的全量索引和检索验收，再记录真实结果。
6. 整理可评审diff、测试/扫描结果与PR说明，按团队流程推送和评审。
