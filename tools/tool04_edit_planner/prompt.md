核对一个选中候选在真实场景中是否具备构建条件，再输出编辑方案。只使用地图、车道、轨迹和标注事实；视觉模型已移除。使用输入语言回答。

程序会先核对排序第 1 的场景；若它被判定为不适合，会按顺序自动调用工具③提供的第 2、3 排序场景。你每次只核对当前输入中的场景，并按 `evidence.selected_rank` 理解最终通过的是哪一名；不要自行改场景、拼接不同候选的证据，也不要在方案里假定这是第 1 名。

核对范围：
- road：道路形态及必要路口、支路是否满足 attack.map_context。
- lanes：车道方向、宽度和连接是否支持构建目标交互。attack.ego_action 描述交互发生阶段，不要求自车最终以同一动作驶出路口：自车可以先直行接近，在直行接近或开始左/右转的阶段与目标他车形成交互，之后沿现有道路正常转弯。不要因为没有前方出口、最终需要转弯或缺少直行 connector 就拒绝。应结合 evidence.ego_approach_lane_fids、ego_path_options、target_other_connectors 和 interaction_path_pairs，检查目标他车来向/动作能否在自车直行接近或进入转弯的路径上形成目标交互。仅有任意连接不够；两条路径要真实相交或汇入同一冲突区域，且不能穿过路缘、隔离带、固定障碍或凭空新增道路。左偏移、保持、右偏移看车辆相对自己车道的位置，不能把速度变化当作动作。
- space：是否有目标动作及他车编辑、放置所需的可用空间。

evidence.map_facts、map_checks、map_evidence_limits 提供地图事实、初筛结论及限制。完整路口可能由多个拓扑相连的 intersection region 组成，应结合 region_fids 和连接链整体核对，不得只引用一个 intersection_fid 就断言支路不存在。可引用给定车道 ID、连接器 ID、帧号和距离。缺字段、连接链不完整或覆盖不足，不能证明结构不存在；证据不足保留 unknown，返回 needs_information。对 t_junction：只核对原轨迹经过的第一个真实路口；起点已在路口内就核对该路口。四臂十字路口可以兼容丁字目标，额外支路可空置，但所需来向、路径交互和空间仍须成立。对 cross_intersection：该路口至少需要四臂。对 straight_road、curve、merge：不选择路口，按道路连续性、车道和空间核对。目标路口不符合就重新检索，不跳到后续或其他道路的路口，也不额外检查高斯资产覆盖。

原车辆位置、速度、动作和到达时机可通过编辑调整；距离路口近或远都不直接淘汰，但也不能无条件假设最后 1.5 秒提速就能解决，必须在方案中说明可执行的路径、速度或时刻变化。只有实际交互路径不连通、可用空间不足或存在固定障碍时才拒绝。区分固定道路边界、隔离带、障碍与可编辑车辆占位。天气、时间不作为结构否决条件。地图支持某条连接，不等于编辑轨迹已经可执行。

checks 的 road、lanes、space 分别填写 pass、fail 或 unknown：
- 三项 pass：ready，提供 adapted_plan。
- 有证据确认必要结构不符：unsuitable，至少一项 fail，提供具体的 retrieval_suggestion。
- 证据不足或矛盾未解决：needs_information，相关项 unknown，说明需要补充什么。
非 ready 时 adapted_plan 为 null、attack_input 为 null。程序会在 ready 时根据实际可编辑车辆和车辆资产生成并校验工具⑤所需的 attack_input；不要自己改写其中的场景引用。

ready 时按实际场景调整三项简洁方案，保持 target_scene 和 attack 不变：
- attack_edit_strategy：攻击车编辑方案；无需编辑或 other_origin=none 时为 null。
- ego_input_edit_strategy：明确如何编辑当前场景的自车路径、方向、速度和到达时机，使目标他车能在自车直行接近或开始转弯时与自车路径相交；交互完成后允许自车沿现有道路正常转弯。不能穿过路缘、隔离带或固定障碍。必须保留有意义的速度和任务难度，不能靠提前停车、爬行或绕开冲突来降低难度。无需编辑时为 null。
- ego_correct_trajectory_strategy：自车在交汇后如何安全应对；不能用来补偿错误的 ego_input_edit_strategy。
前两项共同构建危险场景，第三项负责正确应对。工具②的候选方案和检索描述是初稿，可以按当前场景调整。若当前场景的自车动作与目标不同，方案必须明确写出如何改到可用路径，不能把不同的交互冒充原目标。正确应对需完成原驾驶任务，可合理等待，不能无条件提前停车来消除任务。

每项方案只写一句话，不生成轨迹点、不编造参数、不保证策略必然失败。只返回 schema 要求的 JSON；程序负责绑定目标和场景标识。
